## Construction chain

1. Visual Genome source annotations provide images, objects, attributes, and
   bounding boxes.
2. Metadata mining creates candidate entity pairs. The candidate manifest has
   18,294 unique candidate records.
3. Deterministic geometry, attribute, leakage, image decode, and checksum gates
   construct families. The protocol permits at most two families for one image.
4. The present selected set contains 1,400 `AUTO_VALID` families.
5. Every selected referent still carries
   `HUMAN_UNIQUENESS_CHECK_REQUIRED`.
6. `audit_export.py` accepts only explicit `HUMAN_ACCEPTED` decisions for
   export. It then writes the frozen files and records `DATASET_FROZEN`.
7. The database currently has zero `HUMAN_ACCEPTED`, zero `FROZEN`, and zero
   `DATASET_FROZEN` events. The frozen directory has no release export.

## Why 1,400 families map to 973 images

`REALBIND2_UNIT = FAMILY, NOT UNIQUE IMAGE`

The protocol deliberately permits two different entity-pair families from the
same source image. The observed distribution is:

| Families per source image | Source images | Families contributed |
|---:|---:|---:|
| 1 | 546 | 546 |
| 2 | 427 | 854 |
| **Total** | **973** | **1,400** |

The maximum is two, exactly matching the protocol. There are no duplicate
family IDs, ordered entity-pair IDs, unordered entity-pair IDs, or QA IDs.
This establishes Possibility A/C: family is an entity-pair task unit, and one
image can legally contribute multiple families. It is incorrect to describe
the current snapshot as 1,400 unique images.

The complete mapping is in `data_audit/family_image_mapping.csv`; image paths
there are relative to the construction root.

## Freeze decision

`DATASET_NOT_FROZEN`

Historical protocol and code make human acceptance mandatory. There is no
evidence that this gate was cancelled or replaced by automated certification.
The current `data/realbind2_manifest.json` is therefore explicitly a
nonfrozen construction snapshot. `data/REALBIND2_FROZEN.sha256` was not
created.
